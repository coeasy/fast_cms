# 部署形态与一致性矩阵

> 由第四轮评审（`架构评审与重构方案-2026-10-29.md`）的 **3-3 / A-9 / 3-6** 落地时建立。
> 目的：让「横向扩展能力」有单一事实源（A-5），并回答「哪种部署形态合法、需要哪些前置」。
> 校验入口：`python scripts/env_check.py`（`fastcms doctor` 会打印组合校验）。

## 1. 部署形态

Fast CMS 由单个 FastAPI 进程承载 API + 后台 + 前台，调度器有三种归属：

| 形态 | 调度器归属 | `SCHEDULER_MODE` | 适用 |
|---|---|---|---|
| 单进程（默认） | 应用进程内嵌 | `embedded` | 本地开发、单机小站 |
| 多 worker + 独立调度 | 独立调度进程 | `standalone` | 生产水平扩展（推荐） |
| 无调度 | 无 | `disabled` | 纯 API 网关 / 不需要定时任务 |
| 多 worker + 内嵌（不推荐） | 每个 worker 各自内嵌 | `embedded` + `SCHEDULER_EMBEDDED_MULTIWORKER=true` | 仅接受风险时显式开启 |

## 2. 一致性矩阵

「多实例」指 `APP_WORKERS>1` 或调度器独立运行。各组合是否一致：

| 组合 | Redis | 调度器 | 一致性 | 说明 |
|---|---|---|---|---|
| 单进程 | 任意 | embedded/disabled | ✅ 一致 | 默认形态，无跨进程问题 |
| 多 worker | ✅ 已启用 | standalone | ✅ 一致 | 推荐生产形态 |
| 多 worker | ✅ 已启用 | disabled | ✅ 一致 | 无调度，缓存经 Redis 共享 |
| 多 worker | ❌ 未启用 | standalone | ⚠️ 警告 | 字典/参数等进程内缓存跨进程不一致 |
| 多 worker | ❌ 未启用 | embedded | ⛔ 拒绝 | 后端启动即 `RuntimeError`（见 §4） |
| 多 worker | ❌ 未启用 | embedded + 显式开启 | ⚠️ 警告 | 任务可能重复执行、`next_run_at` 抖动 |

`fastcms doctor` 的 **部署组合** 项会对上述 ⚠️/⛔ 组合给出提示，启动前即可发现。

## 3. `next_run_at` 单一写者（A-9 / 3-6）

`next_run_at`（下次执行时间）只能由一个写者维护，否则多实例下会抖动：

- **embedded / disabled**：API 进程是唯一写者（`api_owns_next_run()` 为真）。
- **standalone**：独立调度进程是唯一写者；**API 进程只读**，`create_job` / `update_job` /
  `set_job_state` 不再写 `next_run_at`（由调度进程 `sync_all()` 计算落库）。

> 判断规则见 `backend/app/modules/ops/schedule/scheduler.py::api_owns_next_run()`。

## 4. 嵌入式调度器 + 多 worker 的开关（3-6）

多 worker 各自持有嵌入式调度器是**不合法**形态（任务重复执行、`next_run_at` 抖动），
后端启动默认拒绝：

- 默认（`SCHEDULER_EMBEDDED_MULTIWORKER` 未设或 `false`）：`APP_WORKERS>1` 且
  `SCHEDULER_MODE=embedded` 时启动抛 `RuntimeError`。
- 显式 `SCHEDULER_EMBEDDED_MULTIWORKER=true`：放行但打启动警告；依赖任务租约
  （`sys_job_lock`）与 `max_instances=1` 作为最后防线，**不保证** `next_run_at` 不抖动。

> 决策函数见 `backend/app/startup.py::embedded_multiworker_policy()`。

## 5. 事件发件箱与多实例（3-2）

事务性事件发件箱（`sys_event_outbox`）由内置任务 `event.outbox_drain` 轮询派发
（默认每 30 秒，多实例经 `event:outbox_drain` 分布式锁去重）。因此：

- **必须**有任一实例启用了 `event.outbox_drain`（种子默认启用）；
- `standalone` 形态下应由调度进程消费，API 进程只负责 `enqueue_event` 写发件箱；
- 事件投递成败可在管理端「事件投递日志」查询（`/monitor/event-logs`）。

## 6. 相关配置

| 配置 | 默认 | 说明 |
|---|---|---|
| `SCHEDULER_MODE` | `embedded` | `embedded` / `standalone` / `disabled` |
| `SCHEDULER_EMBEDDED_MULTIWORKER` | `false` | 显式允许多 worker 内嵌调度器（自担风险） |
| `APP_WORKERS` | `1` | uvicorn worker 数（生产多进程时用 `--workers N`） |
| `REDIS_ENABLED` | `false` | 多 worker 共享缓存需启用 |
