## 1. 系统架构与模块边界（已验证）

### 1.1 运行架构

```
浏览器
 ├─ GET /admin/**       （Jinja2 SSR 页面 + 原生 ES Module，无前端构建）
 ├─ GET /front/**       （前台 SSR 页面）
 └─ /api/v1/**          （JSON 信封，Bearer JWT + API Key）
        │
   FastAPI（app/main.py:create_app）
   ├─ 中间件链（注册顺序=执行逆序，main.py:140-149）
   │    RequestContextMiddleware → IpGuardMiddleware → RateLimitMiddleware
   │    → OperationLogMiddleware →（可选 CORSMiddleware）
   ├─ 异常处理：AppError / RequestValidationError / StarletteHTTPException / 全局 Exception
   ├─ 路由注册：auth / theme / system / config / audit / monitor / dashboard
   │            / export / schedule / security / content / notify / codegen
   ├─ 页面挂载：VersionedStaticFiles + build_admin_router / build_portal_router
   └─ 生命周期 lifespan（main.py:75-113）
        ├─ init_cache（Memory 或 Redis，core/cache.py）
        ├─ ipgeo.startup（ip2region xdb）
        ├─ BootLock（多 worker 首启串行化引导，core/boot_lock.py）
        ├─ ensure_database（Alembic 迁移检查，db/migrate.py）
        ├─ _ensure_seed（种子/权限码同步，bootstrap/seed.py）
        ├─ load_timezone_from_db（system.timezone 参数优先）
        └─ scheduler_service.start（仅 SCHEDULER_MODE=embedded）
```

## 2. 核心链路

### 2.1 认证与会话

`POST /auth/login`（`modules/auth/router.py:51`）→ `auth/service.py:login`：

1. 服务账号前缀 `svc_` 显式拒绝登录（`service.py:51`）。
2. `verify_login_password`：用户不存在也走一次 Argon2（`core/security.py:47-49`），防计时枚举。
3. 失败计数用 SQL 自增（`service.py:73-82`），达阈值锁定 `locked_until`。
4. 封禁/禁用/锁定分别返回 403/423/401，附原因与解封时间（`service.py:94-120`）。
5. 创建 `UserSession`（refresh 只存 sha256），签发 access JWT（`sub/sid/ver/iss/aud/iat/exp/jti`）。
6. refresh token 写入 HttpOnly Cookie（`SameSite=Lax`，`Secure` 由 `AUTH_COOKIE_SECURE`/环境推导，`modules/auth/router.py:29-38`）。

刷新链路（`auth/service.py:refresh_session`）：旧 refresh 命中 `previous_refresh_token_hash` 即判定**重放攻击**并撤销会话（`service.py:170-175`）；轮换用条件 UPDATE 做乐观锁（`service.py:186-206`）。

鉴权依赖（`core/authz.py:_context_from_token`）：用户状态 → 封禁 → 会话存在/未撤销/未过期 → `token_version` 匹配 → 强制改密白名单 → 权限集从数据库实时装载。

### 2.2 权限模型

- **单一事实源**：`bootstrap/permissions.py` 声明 113 个权限码；`bootstrap/menus.py` 菜单引用权限码；路由通过 `PermissionAPIRouter(permission=...)`（`core/routing.py`）注入 `require_permission` 并写入 OpenAPI `x-permission`。
- **超管**：`is_superuser` 绕过权限码检查但仍走会话/审计（`authz.py:52-58`）。
- **API Key**：`fck_` 前缀分流；scopes 即权限集；`*` 声明全部权限（`authz.py:_context_from_api_key`）；创建端校验 scopes ⊆ 创建人权限（`security/service.py:482-504`）。
- **数据范围**：`get_data_scope`（all/self/dept/dept_and_below/custom）+ `apply_user_scope`；审计日志按 `user_id` 关联裁剪，`user_id` 空的孤儿行仅超管/全量可清理（`audit/service.py:116-140`）。
- **防提权**：`_load_roles_for_assignment` 与 `assign_role_permissions` 均要求权限集 ⊆ 操作者权限、数据范围 ⊆ 操作者范围（`system/service.py:193-220`、`676-712`）；`_last_superuser_guard` 保证至少留一个超管（`system/service.py:179-191`）。

### 2.3 调度任务链路

`sys_job`（事实源）→ `SchedulerService.sync_all`（`schedule/scheduler.py:124-186`）→ `run_job`（`jobs/runner.py`）：

1. `build_trigger` 支持 cron/interval/date，`anchor` 用库中 `next_run_at` 锚定 interval 相位（`scheduler.py:41-58`）。
2. 执行前 `acquire_locks([f"job:{id}"])` 数据库租约（`schedule/locks.py`），TTL=max(60, timeout+60)，执行期间 `renew_with_retry` 续租。
3. 写 `running` 日志 + `run_token`；超时用 `asyncio.wait_for`；输出/错误截断 32KB。
4. 崩溃恢复 `recover_interrupted_logs`：无活跃租约的 `running` 标记 `interrupted`。
5. 一次性 date 任务调度执行完自动 `paused`（`runner.py:204-208`）。
6. 失败/中断触发 `notify.hooks.job_finished` 入队通知。
7. 三种模式：`embedded`（单 worker，`APP_WORKERS>1` 启动即抛）、`standalone`（`app.cli scheduler`）、`disabled`。

- 迁移链：`c9ce1cf0f9c2`(初始) → `b7a1c2d3e4f5`(job code 唯一→非唯一) → `e3f4a5b6c7d8`(模板/锁/主题) → `583727afcb2f`(通知) → `d4e5f6a7b8c9`(IP 规则/API Key/封禁) → `a1b2c3d4e5f6`(API Key 服务账号) → `b2c3d4e5f6a7`(登录日志 location)。
