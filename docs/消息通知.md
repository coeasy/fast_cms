# 消息通知

Fast CMS 的通知能力把「谁触发」与「谁发送」解耦：业务事件只负责把消息入队，真正的 HTTP 推送由定时任务 `notify.dispatch` 完成。默认覆盖两类固定触发点（定时任务失败/中断、公告发布），支持钉钉、飞书、企业微信与通用 Webhook 四种渠道，**不依赖 Redis 或外部队列**。

## 1. 运行模型

```text
触发点                                  渠道配置
├─ app/jobs/runner.py（执行结束）        sys_notify_channel（events 订阅 + 状态）
└─ app/modules/content/service.py（发布）
        │  hooks.py 组装标题与正文
        ▼
sys_notify_record（按渠道逐条入队）
        │  唯一键 (channel_id, event, dedupe_key)
        ▼
notify.dispatch（每 60 秒，默认暂停）
        │  行级抢占 pending → sending
        ▼
channels.send_markdown（钉钉 / 飞书 / 企业微信 / 通用 Webhook）
        ▼
success / failed（退避后重新 pending）/ skipped
```

- 消息**先进数据库再发送**：请求线程不做外网调用，IM 超时或宕机不会拖慢后台接口；
- 同一条消息对同一个渠道只入队一次，唯一键冲突直接忽略（用 `SAVEPOINT` 吞掉 `IntegrityError`），因此任务重跑、公告重复发布不会产生重复消息；
- 记录状态：`pending`（待发送）→ `sending`（已抢占）→ `success` / `failed` / `skipped`（渠道已删除或停用）；
- 抢占使用 `UPDATE ... WHERE status='pending'` 的行级条件更新，多个 worker 同时执行投递任务也不会重复发送同一条记录；
- `sending` 超过 300 秒未回写视为投递进程被杀，下一轮自动回到待发送；
- 重试为指数退避：60 秒起，逐次翻倍，最长 1800 秒；达到 `NOTIFY_MAX_ATTEMPTS` 后置为 `failed`，不再自动重试，可在页面手工重试。

## 2. 渠道与消息格式

| 类型 | 消息体 | 签名 | 成功判定 |
|---|---|---|---|
| `dingtalk` | `msgtype=markdown`，正文以 `### 标题` 开头 | 传密钥时按 `timestamp\n密钥` 做 HmacSHA256 → Base64 → URL 编码，追加 `timestamp`/`sign` 查询参数 | `errcode == 0` |
| `feishu` | `msg_type=text` | 传密钥时以 `timestamp\n密钥` 为 key 对空串做 HmacSHA256 → Base64，写入请求体 `timestamp`/`sign` | `code == 0` 或 `errcode == 0` |
| `wecom` | `msgtype=markdown` | 平台不支持加签，填写密钥会直接判定失败并提示清空 | `errcode == 0` |
| `webhook` | `{title, content, markdown, event, dedupe_key}` | 无 | HTTP 2xx |

非 2xx 与 3xx 都记为失败，响应体前 200 字符写入 `last_error`，便于在发送记录里直接定位配置问题（token 失效、关键词未命中、IP 白名单等）。

## 3. 触发点

| 事件 | 触发位置 | 去重键 | 说明 |
|---|---|---|---|
| `job.failed` | `app/jobs/runner.py` 执行结束 | `job_log:{log_id}` | 任务执行抛错或超时，正文含任务名、编码、触发方式、耗时与错误摘要 |
| `job.interrupted` | 同上 | `job_log:{log_id}` | 进程重启导致的执行中断 |
| `notice.published` | `app/modules/content/service.py` | `notice:{notice_id}` | 点击发布、以及直接创建为「已发布」的公告都会入队 |
| `test` | 渠道「测试」按钮 | 随机 UUID | 同步投递一次，用于验证配置；失败不进入自动重试队列 |

- 只有状态为 `enabled` 且 `events` 包含该事件的渠道会收到消息；渠道被停用后，此前入队的记录在下轮投递时置为 `skipped`；
- 触发侧异常一律吞掉并记录日志，通知失败不会影响业务事务；
- `NOTIFY_ENABLED=false` 时触发点直接跳过入队，已在队列中的记录也不会再投递。

## 4. 投递任务

`notify.dispatch`（内置任务）默认**已暂停**，避免未配置渠道时刷执行日志。配置好渠道后在「定时任务」中恢复，或先手动「执行」一次验证链路。

| 参数 | 默认 | 说明 |
|---|---|---|
| `limit` | `20` | 单轮抢占的待发送记录数，范围 1-100 |

任务结果字符串形如 `claimed=2 failed=0 pending=0 skipped=0 success=2`。多 worker 部署时依赖任务租约去重，同编码任务不会并发执行。

发送记录的清理有两个入口：`system.cleanup_logs` 任务按保留天数一并删除通知记录，或在「发送记录 → 清理记录」按天手工清理（1-3650 天）。

## 5. 凭证与 SSRF 边界

webhook 地址本身就带 `access_token`/`key`，按凭证对待：

- 所有接口只返回 `webhook_url_masked`（去掉账号密码段、掩码全部查询参数值与 20 字符以上的路径段）与 `has_secret`，不回显密钥原文；
- 更新时「留空 = 保留原值」，避免脱敏回显被再次提交后覆盖成掩码串；
- 审计日志的 `SENSITIVE_KEYS` 包含 `webhook_url`，请求体入库前即完成脱敏；
- 密钥当前以明文存储在 `sys_notify_channel.secret`，读写仅限管理员接口；需要静态加密时可在 `service.create_channel/update_channel` 处接入加解密，接口层无需改动。

推送地址的校验（`channels.validate_webhook_url`）：

- 强制 HTTPS，仅非生产环境允许 HTTP；
- 拒绝空地址、超长（>1000）、缺主机名、含账号密码、含锚点、非默认端口；
- 解析域名后逐个 IP 校验，拒绝私网、回环、链路本地、组播、保留与未指定地址；
- 请求关闭重定向跟随（`follow_redirects=False`），避免外网地址跳到内网。

上述内网与端口限制仅可由 `NOTIFY_ALLOW_PRIVATE_TARGET=true` 放开，用于本地联调或自建内网网关；生产环境保持默认关闭。

## 6. 页面、权限与环境变量

菜单「消息通知」下两个页面，路由整体受 `require_admin` 保护，非管理员无法访问任何通知接口。

| 权限码 | 作用 |
|---|---|
| `notify:channel:list` / `create` / `update` / `delete` | 渠道增删改查 |
| `notify:channel:test` | 发送测试消息 |
| `notify:record:list` / `retry` / `delete` | 发送记录查看、手工重试、清理 |

| 环境变量 | 默认 | 说明 |
|---|---|---|
| `NOTIFY_ENABLED` | `true` | 通知总开关 |
| `NOTIFY_TIMEOUT_SECONDS` | `10` | 单次推送 HTTP 超时（收敛到 1-60） |
| `NOTIFY_MAX_ATTEMPTS` | `5` | 自动重试上限，达到后置为 `failed` |
| `NOTIFY_BATCH_SIZE` | `20` | 单轮投递取出的记录数（收敛到 1-60） |
| `NOTIFY_ALLOW_PRIVATE_TARGET` | `false` | 放开内网地址与非默认端口，仅供联调 |

数据表 `sys_notify_channel`、`sys_notify_record` 由迁移 `583727afcb2f_notify_channels_and_send_records` 创建；升级后需执行 `python -m app.cli db upgrade` 与 `python -m app.cli seed` 同步内置任务模板与字典。

## 7. 常见问题

| 现象 | 原因与处理 |
|---|---|
| 渠道测试成功，但公告发布后一直是「待发送」 | `notify.dispatch` 未启用，恢复该任务即可 |
| 创建渠道返回 `NOTIFY_URL_INVALID` | 地址非 HTTPS、指向内网或带非默认端口；本地联调需临时设 `NOTIFY_ALLOW_PRIVATE_TARGET=true` |
| 企业微信渠道始终失败并提示不支持加签 | 清空签名密钥，密钥只用于钉钉加签与飞书签名校验 |
| 记录显示 `skipped` | 渠道已删除或已停用，消息不会发送；重新启用渠道后手工重试 |
| 换 IM 群后旧密钥丢失 | 直接编辑渠道填写新地址与密钥；无法查看历史原文 |
